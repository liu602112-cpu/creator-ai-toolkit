## 公开发布版

这是便于复用的公开版，原始私人语料、声音参考、商业音乐和第三方媒体不随包提供。依赖、输入和输出见同目录 README.md。样例数据明确标为演示，不代表真实效果。


# 我的声音与形象 → 数字人口播

目标是交付可播放、可下载的 MP4，不以创建任务或返回任务 ID 代替成片。用户说“对齐”时，只沟通目标，不执行。

## 素材与默认选择

- 用户提供成品配音：原音频作为驱动音轨，保留音色、文案和语速，不再转成文字让飞影重新配音。
- 用户提供声音参考和文案：先克隆生成目标文案，再以生成音频驱动形象。用户说“克隆音”但无法判断是成品还是参考时，先检查时长、转写与文案匹配度；仍不明确才询问。
- 用户提供形象视频：保留本人形象、背景和原始画幅；不替换公共数字人，不擅自裁切或加模板、音乐、字幕。
- 只缺形象视频时，可继续准备配音，但不能宣称数字人已制作。只有用户提供并明确指定的形象素材才可成为默认形象。
- 默认一条正常语速作品。1.1 倍或多个版本只在用户要求时制作；不要把历史双版本要求应用于所有任务。
- 已有成品音频时，通常只需上传音频和形象视频，使用声音驱动接口；无需额外创建付费声音资源或持久数字人资源。用户明确要求长期创建资源时才走对应流程。

## 配音入口

优先使用用户提供的成品配音。如需生成新配音，读取用户配置的 Fish Audio 入口与授权声音参考；本公开版不携带任何默认声音、形象或服务密钥。

## 执行

1. 在当前可写工作区建立 `avatar-video-content/YYYY-MM-DD/主题/` 项目目录。记录文案、输入路径与哈希、音频用途、速度、画幅、版本数。保留原件和已有输出，不覆盖。
2. 检查音视频可解码、音频时长、视频尺寸/编码/时长，抽查开头、中间和结尾画面，识别人脸是否清楚、是否多人或明显遮挡。必要格式转换另存文件。不要凭文件扩展名判断合格。
3. 需要生成配音时，使用用户文案原文，核对公式、数字和专有名词的成品转写；有实质差异先修正。不要擅自润色文案。默认使用现有 Fish Audio 模型，不自动升级收费模型。
4. 飞影优先使用当前已连接的 `hifly` MCP，发现真实工具和参数后调用。读取账户状态；若 MCP 缺少所需字段或不可用，可依据用户提供的官方 API 文档使用直接接口，不猜测资源 ID。接口与关键边界见 [references/hifly.md](references/hifly.md)。
5. 创建前用简短更新说明将使用的具体音频、形象、版本数及已知消耗；不编造积分报价。用户明确要求按这些素材制作时即有该范围内授权，不人为追加确认关卡。若平台要求额外确认、自动审批拦截或请求仍有关键歧义，说明具体原因，只问缺少的信息。仅创建 skill 不代表授权立即上传或生成作品。
6. 上传素材时先申请上传地址，再 PUT 原始文件内容；成功后才使用 file_id。对象存储上传不附带飞影凭证。分清音频 file_id 与 video_file_id。
7. 创建音频驱动视频，每个确认版本仅提交一次。立即记录任务 ID、请求 ID、参数摘要和状态，不保存密钥或含临时签名的上传 URL。网络超时导致提交结果不明时，不盲目重发；先检查已有记录和服务状态。
8. 对已提交任务作有间隔、有限次数的只读状态查询，尊重服务限流和当前工具约束；等待不能触发重复创建。任务失败保留错误及任务记录，未经用户授权不另建替代作品。长时间未完成时如实报告状态，不称完成；用户要求稍后跟进时使用可用自动化能力。
9. 完成后将成片下载到项目目录并解码检查：有画面、有音轨、时长合理、无意外截断；抽查口型同步及头中尾画面，核对音轨与原配音。无法验证的项目明确说明。交付内嵌 MP4 或下载链接及必要的配音文件，不发布到社交平台。

## 凭证与复用

- 飞影配置为 `https://hifly.cc/mcp`，凭证从 `HIFLY_API_TOKEN` 获取；Windows 用户环境变量已配置时，当前进程可能需重新加载。不要把凭证写入 skill、项目清单、代码或回复。
- Fish Audio 使用本机加密密钥；隔离环境无法解密时按运行环境要求使用当前用户上下文，不打印解密内容。
- 资源 ID 仅来自本次实际服务返回、用户明确提供或经核验的项目清单。资源变更及失败不能通过替换公共人物/声音来绕过。
- 用户以后指定默认形象时，保存素材备份和来源记录；不要擅自迁移或删除桌面原件。重复使用时核验文件哈希和资源可访问性。
