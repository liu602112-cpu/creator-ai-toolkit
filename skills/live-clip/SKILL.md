## Windows 适配说明

本版为学员版 v3 的 Windows/Codex 改编（2026-10-05，v3-windows.1），保留喂鱼原始署名。用户指令优先于源包流程；用户已明确选题、开头或从哪一步做起时，直接沿用，不重复要求确认。用户说“对齐”时只交流目标。

- 全局安装位置：`$CODEX_HOME/skills`；未设置时为 `%USERPROFILE%/.codex/skills`。关联脚本按两个 Skill 的相邻目录定位。
- 自动发现 Windows 剪映、CapCut 的默认草稿目录；非默认目录通过 `JY_DRAFT_ROOT` 指定。
- 入口在相邻 `jianying-draft/scripts/run-jy.ps1`，支持 `jy_pack` 和 `jy_audit`；先通过该入口运行 `jy_doctor` 检查环境。
- 同时支持 `draft_content.json` 和 `draft_info.json`，保留源文件的明文或加密形式。只在副本和新草稿上工作；写真实草稿前检测剪映是否运行，不自动退出剪映。
- 使用源画布及帧率。精剪默认保留原音量和声道；用户要求响度处理时才设置 `loudness_target`。源包的 -13 LUFS 是作者示例参数，不代表本用户已确认。下文的“用户”、0926/1001反馈和个人预设均为源作者案例，不能当成当前用户经历。成片时长以当前用户要求和内容完整性为准。
- 源包字幕样式可继续使用；字体路径在读取预设时结构化转换。公开版不附带字体或音效。使用用户自己取得许可的字体；可通过 `LIVE_CLIP_FONT_CN` / `LIVE_CLIP_FONT_EN` 指定，缺失时报告并采用系统字体。
- 已合入 v3 的 35 个音效，按包装方案选用；模糊特效没有本机缓存时保留压暗，不写入 Mac 缓存路径。首次正式使用要在剪映检查字体、动画和特效。
- 先完成 dry-run 和副本自检；脚本校验通过不等于剪映已打开或视频已播放验证。

# 剪映源代码

原型：0926 直播 → 6 条切片 → 「靠AI视频找工作的三条路」可视化版，完整参数见 `references/example-0926/`。单条包装（重点字精简 + 主页截图 B-roll，带合成脚本）的范例见 `references/example-0926切1/`。问答 / 采访素材的范例见 `references/example-1001/`（1001拍摄，9 条，去掉提问人，带 edge 参数）。

| 用到的东西 | 位置 |
|---|---|
| 读取、解密、切条、精剪 | `~/.codex/skills/jianying-draft/scripts/`（`jy.py`、`jy_cut.py`、`jy_tighten.py`） |
| 包装 | 本 skill 的 `scripts/jy_pack.py` |

## 流程：四步

| 步骤 | 做什么 | 交付与必要选择 |
|---|---|---|
| 0. 判断入口 | 按当前指令和草稿状态确定入口 | 已明确时直接继续；有歧义才询问 |
| 1. 挑切片 / 找选题 | 读整场直播，挑出 4–6 个能单独成立的观点 | 确认挑哪几条 |
| 2. 想开头 | 每条出 2–3 版开头，带开头包 | 每条选一版 |
| 3. 精剪 | 按选定的开头拼接，剪气口和口误，字幕断行、校对 | 用户在剪映里改一版 |
| 4. 包装 | 在用户改过的版本上加重点字、卡片、B-roll、音效 | 看成片后微调 |

### 0. 判断入口，沿用已有决定
用户给的不一定是整场直播，所以先看这个草稿现在到了哪一步：
- 草稿名、时长：是整场直播（几十分钟），还是已经切好的「xx切N_标题」（1–2 分钟）。
- 有没有 `.jy_backup_*` 目录：有就说明精剪脚本写过。
- 修改时间：`.jy_backup_*` 之后又被剪映保存过，说明用户自己改过一版。
- **体检字幕和声音**：`python ~/.codex/skills/live-clip/scripts/jy_audit.py <草稿>`（只读）。查三项：字幕是不是个人预设（字体、字号、加粗、字色、阴影、底框）、声道配置对不对（单边录音要填充）、当前响度是多少。字幕预设可套用，声道和音量仅按当前用户要求处理；但从第 4 步进来、或者草稿是这套规则之前剪的，就可能没套，包装脚本会原样照搬。0926切1 就是这样：字幕对，但音量一直是 0 dB，只有 -32 LUFS，差了 19 dB。

仅当入口或范围仍有歧义时，提出明确问题，例如：
> 这条已经切好、精剪过，你 9/28 也改过一版。我打算在你改的版本上**再精剪一遍，然后包装**，开头不动。可以吗？

体检标记是相对源作者样式的差异，不自动代表当前工程错误。报告具体测量结果；没有音量处理要求时保留原音量。

用户的话要照字面做：说「精剪包装」就两步都做，**不能因为以前精剪过就跳过精剪**（0926切1 的教训）。只有用户明确说了从哪步做起（比如「直接包装」），才不用再问。
从中间步骤进来时，前面没做的步骤不补，但如果发现明显的问题（开头太弱、字幕断行不顺），要说出来并给出建议。

```powershell
$SkillRoot = if ($env:CODEX_HOME) { Join-Path $env:CODEX_HOME "skills" } else { Join-Path $env:USERPROFILE ".codex/skills" }
$JY = Join-Path $SkillRoot "jianying-draft/scripts"
$LC = Join-Path $SkillRoot "live-clip/scripts"
$Runner = Join-Path $JY "run-jy.ps1"
```

### 1. 挑切片 / 找选题
```powershell
& $Runner jy list -n 10
& $Runner jy summary <直播草稿> --texts 0
& $Runner jy srt <直播草稿> --txt
```
1. 把逐字稿按分钟整理成内容地图，标出：每个观点段的起止时间、闲聊和互动段、课程价格等敏感段、录制断档的位置。大疆这类原片的文件名里带录制时间，相邻两段文件名时间差明显大于片长的地方，就是断档。
2. **问答 / 采访素材**（比如「1001拍摄」：对面有人提问，用户作答）：切片里**不留提问人的声音**，每条只留用户的回答。区间要从回答的第一句开始，提问人插的「嗯」「对」「哦明白了」整行删掉。回答第一句如果依赖问题才能听懂（比如「你说的月薪过万……」），就换一个能单独成立的句子当开头。
3. 按 `references/selection.md` 筛选，数量和时长优先按当前用户要求，不为压时长删掉必要观点。用一张表给用户确认，列出：标题方向、时间段、时长、核心观点、剪辑处理（调换顺序、删哪段）。另外单独列出建议不用的段落和理由，以及需要用户确认的词（人名、产品名、型号、金额）。**需要选择时等用户选择；当前用户已明确要做哪条时继续第 2 步。**

### 2. 想开头
切片的开头是**从这段里选出来的**，不是重写；直播里最狠的那句往往在中间或结尾。开头要在精剪之前定下来，精剪时才知道把哪句挪到最前、正文从哪接回来。
1. 方法见 `references/selection.md`「开头怎么挑」，以及随包附带的 `references/hook/opening-package.md`、`references/hook/hook-patterns.md`、`references/hook/hook-bank.md`，不需要另装 hook-opening。
2. 每条出 2–3 版开头，尽量用不同的式子。每版写清楚：
   - 口播第一句（源时间线上的时间，可以从几个短句拼起来）；
   - 承接句：开头后面接回正文的第一句；
   - 第一帧画面和屏幕大字（包装时第一个重点字就用它）；
   - 用的什么式子，为什么选它。
3. 标出推荐的那一版，让用户每条选一版。**存在未决选择时等用户选择；已有明确开头时直接继续第 3 步。**
4. 用户已经在剪映里改过的草稿，开头只给方案，不重新生成。
5. 同时按 `references/publish-pack.md` 给出标题、封面主副字、正文与标签；读 `config.json` 的实际受众，空值时按当前素材和用户背景判断，作者示例不能当成用户定位。用户要求飞书同步时，使用已配置表；未配置就先交付本地发布包，按用户要求再选表或建表。

### 3. 精剪
1. 写 `cut.json`，格式参考 `references/example-0926/cut.json`。每条填 `name`、`ranges`（源时间线上的秒数，按先后拼接；选定的开头区间放在第一个）和 `script`（断句稿文件名）。
   - 区间两端要对齐字幕的起止时间：用 `jy.py decrypt` 把字幕连同毫秒时间列出来，再定切点。
   - 同一条里调换顺序时，要保证代词前后能对上。
   - 开头那句在正文里原样又出现一次的，正文里那次通常删掉或缩短，除非用户要首尾呼应。
2. 字幕没有逐字时间时，先用 jianying-draft 的 `jy_check` 渲染时间线音频，再用 Whisper 和 `jy_words` 生成 `words.json`，在 cut.json 中指定 `"words_file": "words.json"`。v3 可读取草稿占位符路径和主轨中的复合片段音频。导出每条的逐字骨架：`& $Runner jy_tighten cut.json --dump 切1`。
3. 按 `references/editing-rules.md` 修改骨架：删气口、口误和重复；按语义重新断行；标上逗号、句号；校对错字；统一术语写法。
4. 检查并写入：
   - `& $Runner jy_tighten cut.json --dry-run`：把输出的字幕从头读一遍，确认通顺，没有半句话，没有错字。
   - 去掉 `--dry-run` 正式写入。同名草稿会先备份再覆盖，新草稿会自动登记进剪映。**用户改过的草稿不覆盖**，精剪结果写成新草稿（名字加 `_精剪`）。
   - 写入时自动完成（jianying-draft 的默认设置，不用另外跑）：
     - 字幕套用户的个人预设：思源黑体加粗、黑阴影、30% 黑底框。
     - 默认保留原声道，用户要求处理单边录音时才调整。
     - 默认保留原音量；用户要求响度处理时才设置 `loudness_target`。
     - 两个英文词之间的「加」显示成「+」（AI+IP）。
     - 若启用响度处理，交付实际测量结果和调整量。
   - 区间两头漏音：spec 里设 `"edge_pre": 0.25, "edge_post": 0.3`。问答素材的回答常常紧接在提问后面，更要设。
5. **写入后自检（必做）**：`& $Runner jy_check <草稿…>`，按切点拼音频、识别，再和字幕对照。看「识别多出」：多出来的是漏进区间的声音，比如上一句的尾巴，要调区间或 edge 参数后重新生成。看「字幕有、识别没有」：可能是切掉了字，单独截那几秒复听确认，识别本身也会漏词。
6. 交付时写清楚三件事：每条原时长 → 精剪后时长；**根据上下文猜的词**要单独列出来让用户确认（数字、人名、产品名、型号）；连读处的切口需要用户戴耳机听一遍。
7. 若用户要求了飞书同步，精剪后补入当前逐字稿、时长和 Windows 本地路径并回读验证；抽封面用 `& $Runner jy_frames <草稿> <输出目录> --n 12 --keywords 关键词`。
8. 用户通常会在剪映里再修一版，比如调顺序、删段落、加美颜。之后的包装以用户改过的那一版为源。

### 4. 包装
1. 开始前先 `summary` 看用户改了什么，再核对三件事：结尾是否完整、字幕有没有被重新识别后改回错字、有没有该合并的断行。有问题先告诉用户。
2. 读用户改过的草稿的字幕，按 `references/pack-spec.md` 写 `pack.json` 分镜。**重点字要少**：一分半左右 8–10 个，只给判断词、金句、数字（「绝对会死」「一人成军」），过渡词和换个说法的复述（「之前稀缺」「养团队」）不做。0926切1 第一版 98 秒放了 23 个，用户嫌太多，删到 9 个才行。
   - 结构段（「分为三类」这种）做目录卡和章节条；
   - 并列的词做逐个弹出的卡片，流程做成链路；
   - **提到具体的人、账号、产品，就插真实截图做的 B-roll**，不要只做文字卡。人和账号截主页，产品截应用页面（取法见 pack-spec「找素材」）。
3. 找素材：优先用真实素材；用户自己的照片先问能不能用。素材存到 `当前工作目录/切片包装/<片名>-可视化素材/`。不确定是哪个人（同名账号多）时，问用户要链接，不要猜。
4. `& $Runner jy_pack pack.json --dry-run`：核对每个元素的出现时间。标了 ⚠ 的重点字停留不到 1.4 秒，要改成从这句话开头出现。
5. 正式写入，输出新草稿，用户改过的原稿不动。写入前确认剪映主程序已退出（`Get-Process JianyingPro,CapCut -ErrorAction SilentlyContinue`），开着的话新草稿可能不显示、登记也可能被覆盖。
6. **按要求补字幕和音量**：只修当前用户指定或已确认的问题，在包装出的新草稿上处理：
   - 字幕：`& $Runner jy_style <新草稿>`，只改字幕样式，重点字、卡片不受影响；
   - 声道和音量：`& $Runner jy_loud <新草稿>`，只调主轨，虚化副本本来就是静音的；
   - 修完再跑一次 `jy_audit.py <新草稿>`，逐项解释与源作者预设的差异，按当前用户要求验收。新草稿已经被剪映打开过的话，这两个脚本会拒绝写，确认后加 `--force`。
7. 交付时提醒用户：
   - 「模糊」特效的本地缓存可能已被清掉，如果虚化没出现，在剪映里手动加一次「模糊」特效，让它重新下载；
   - 字号和位置是估算的，可能需要微调；
   - 如果觉得画面变暗，调低暗角图层的不透明度。

## 默认风格（用户没说换就用这套）
- 字幕：源作者示例预设（`jianying-draft/presets/subtitle_style.json`），思源黑体加粗 8 号、白字黑阴影、30% 黑底框。精剪时自动套用。
- 音量与声道：默认保留源设置；按当前用户明确要求才执行响度或声道处理。
- 重点字：猴尊宋体，渐变 `#FFFFFF → #FFF3B7`，放在画面约 65% 高度处（下巴下方、字幕上方）。英文装饰用 Cherolina，颜色 `#FFEC8A`，压在中文右下角。入场动画都是「扭曲模糊」。
- 重点色 `#FFEC8A`：只用在编号、金额、判断词上，一个画面最多一处。
- 运镜：每个跳切在 1.0 和 1.08 两档之间交替轻推，每段内匀速慢推（片段 4 秒推 3.5%）。
- 对焦：卡片和 B-roll 出现时，口播画面淡入虚化并压暗；结束时淡出，画面重新变清楚。
- 全片加暗角和底部压暗，给重点字托底。
- 音效：放进 `~/.codex/skills/live-clip/assets/sfx/`，或用环境变量 `LIVE_CLIP_SFX` 指定目录。pack.json 里写到的音效文件名（「一次呼.wav」「平移.wav」「收银机.mp3」等）找不到就跳过，不影响其他元素。

## 已知的坑
- **剪映开着或打开过草稿，就会自动保存**，覆盖保护随即生效（`⛔ 被剪映保存过`）。只改样式、音量、声道、字幕文字的时候，用 `jy_style.py` / `jy_loud.py`，或者在现有文件上直接改。这样用户在剪映里的修改会保留，不要为这些小改动重新生成。必须重新生成时，先对比用户改了什么（音量、字幕时间等），生成后把这些改动补回去，并告诉用户。
- **量响度不能混成单声道**。单边录音的左右声道差 6 dB，混了会偏低 3 dB 多；识别用的音频可以混。
- 开头钩子里，动词后面要有宾语：「一个公司里面的销售，他都需要去做」听不出要做什么，用户觉得不抓人（1001切8），后来换成损失式开头「你东西做得再好，别人不知道，就没办法付费」。
- 剪映识别出的逐字时间，偶尔会整体超出这句字幕的时长（约 1.5% 的句子）。精剪脚本会按比例压回；包装时这类句子里用「句/词」取到的时间点会偏晚，所以重点字统一从这句话开头出现，不按具体某个词。
- 同一条轨道里的片段不能在时间上重叠。包装脚本会自动分配轨道，并合并相邻的虚化窗口。
- 用户亲口说的专有名词（比如 K9）不要自作主张改掉，只改明显的识别错误。
- 剪映保存时会把时间对齐到帧（按源草稿帧率），重新打开后出现 1 帧以内的差异是正常的。
