# 剪辑规则：断句稿怎么写

断句稿就是 `jy_tighten.py --dump` 导出来的逐字骨架。**一行就是一条字幕**，字之间用 `|` 隔开。改完之后，所有字的先后顺序必须和原来一样（脚本会逐字核对），换行和标点可以随便改。

## 标记
| 写法 | 含义 |
|---|---|
| `[呃]` | 删掉这个字：音频和字幕一起删 |
| `差{刀}` | 只改字幕上显示的字，音频保留 |
| `g{}` | 字幕上不显示这个字，音频保留，用来合并英文，比如 `AI{AIGC}\|␣{}\|g{}\|␣{}\|c{}` |
| 行首加 `~` | 整行删掉 |
| 行尾或字后面加 `，` `、` | 半句话的停顿，短，默认 0.18 秒 |
| 行尾或字后面加 `。` `？` `！` | 一句话说完的停顿，稍长，默认 0.32 秒 |
| 行尾不写标点 | 按「，」处理，因为换行本身就是一次半句停顿 |
| `␣` | 原字幕里的空格分词 |
| 骨架行尾的 `# 前停 0.47s` | 这句前面实际的静音长度，是判断用句号还是逗号的参考。可以留着，脚本不读 |

字幕里的标点显示规则：行尾的「，。」去掉，「？！」保留；行中间的「，。」显示成空格。

停顿从**尾音收干净**之后才开始算：上一个字说完后，音量要回落到本地底噪 +8dB 以内并保持 120ms，才算这句话说完；到下一个字真正开口（同样按音量判断，不按识别时间）之间的纯安静，压到目标长度。所以尾音和起音都会完整保留，停顿是加在尾音之后的。字和字之间超过 0.3 秒的气口压到 0.12 秒。删掉语气词的地方，也按那里的标点在切口两侧各留一半停顿，不会硬接。

> 2026-10-01 用户反馈：旧版用固定阈值判静音，尾音还在往下落就被当成静音切掉，「话没说完就切了」。改成按底噪判断后，有停顿的切口里切早的从 37 个降到 0（剩下的都是紧跟着要删的字）。这些数值都可以在 `cut.json` 里调：`comma_pause`、`sent_pause`、`word_pause`、`max_gap`。

## 1. 剪气口
- 优先删：句首和句中的「呃」「嗯」「啊」「诶」，句首多余的「就」「那么」「就是」「然后」「所以」，句尾的「啊」「呢」（问句的「呢」保留）。
- 整行删：结巴重复（「我我」「会会」「很很」只留一个），说到一半重来的句子（「20差怎么就」「那什么样子的会可以」→ 保留后面说对的那一遍），内容为零的填充句（「然后这个就是达到了你的一个内容」）。
- 句号还是逗号：
  - **意思说完了**，下一句换了主语或话题，用「。」；
  - **意思没说完**，后面是补充、并列或转折，用「，」；
  - 骨架里「前停」超过 0.5 秒的地方，多半是一句话说完了，但最终还是按意思判断。
- 删字的地方如果前后连着说、中间没有停顿（比如「就明年」「啊1500」），切口会有轻微的跳动感，交付时提醒用户听这几处。

## 2. 字幕断句
**一行只放一个完整的意群**，不能把一个词或一个动作拆到两行。

| ✗ 识别出来的断法 | ✓ 改成 |
|---|---|
| 这是很多AI视频网站点 / 一次生图按钮价格 | 这是很多AI视频网站， / 点一次生图按钮价格 |
| 是因为抖音它之 / 前稀缺这些号 | 是因为抖音它 / 之前稀缺这些号 |
| 比较火的Prompt / Engineering提示词工程 | 比较火的 / Prompt Engineering提示词工程 |
| 并且可以进行一些反馈 / 流转比如说我搭建系统 | 并且可以进行一些反馈流转， / 比如说我搭建系统 |

- 挪字的办法是直接改换行位置：把「点」挪到下一行开头就行，不需要 `{}`。只有一个分词本身被拆开时（比如「之」「前」各属一行），才用 `之{}` / `前{之前}` 改显示。
- **每行最多 13 个字宽**（英文、数字按半个字算）。竖屏 1080 宽、字号 8 的字幕，超过这个宽度会自动折行，甚至被截断出画面。`--dry-run` 会给超长的行标 ⚠，必须拆开。一般 4–12 个字最舒服。
- **行首不能是「的、了、着、地」**：「每个月大概花费 / 的成本是10万」要改成「每个月大概 / 花费的成本是10万」，「这就是黄仁勋说 / 的两个最值钱的」要改成「这就是黄仁勋说的 / 两个最值钱的」。拆长句时最容易出这个错，拆完要再扫一遍。
- 两三个字的碎行（比如「其实」「叫做」），如果后面没有停顿，就并到下一行。
- 并列三项（「甲方的钱、企业的钱、品牌方的钱」），每项单独一行更有节奏感。

### 字幕截断（时间上）
字幕要**跟着声音走，不要跟着识别出来的字时间走**。剪映识别出来的字时间常常偏早、偏短，按它算会出现「人还在说，字幕已经消失」或「人已经开口，字幕还没出来」。
- **出现**：按音量找到开口的时刻（往前最多 0.6 秒），字幕从那里出现。
- **消失**：等这句话的尾音收干净（音量回落到底噪 +8dB 以内并保持 120ms）再消失。和下一条字幕间隔不到 0.5 秒的，就直接接到下一条。
- 精剪脚本已经按这个规则算字幕起止。写入后用「拼音频 + 识别」检查：字幕先消失、或晚于开口出现超过 0.1 秒的，逐条回听。
- 切口切掉半个字时，字幕里也不能留下那半个字（比如「不仅仅是工」）。

## 3. 校对
**逐行读 `--dry-run` 的输出**，重点看这几类：
- **英文和术语**：统一大小写和写法，比如 DeepSeek、GPT-3.5、Prompt Engineering、Context、Harness Engineering、Agent、Codex、Claude、AIGC、FDE、MCN、IP、vlog。常用的写进 `cut.json` 的 `glossary`，会自动统一，但只对单个分词生效。
- **英文词之间的「加」写成「+」**：AI加IP 写成 AI+IP，IP加上IP操盘手 写成 IP+IP操盘手。精剪脚本会自动转换（`plus_join`），只在两个英文或数字词之间生效；「AI加上流量」「这个人加上他的产品」这类后面接中文的不转。只改字幕显示，音频不动。（2026-10-02 用户要求）
- **被识别拆开的英文**：比如 `AI|␣|g|␣|c` 应该是 AIGC，用 `{}` 合并。
- **近音错字**：共同性→共通性，那部快钱→那波快钱，他/它（指物、AI、模型时用「它」），的/地（副词后面用「地」）。
- **结巴字**：策策略岗→策略岗，AAI→AI，发小小红书→发小红书。
- **人名、产品、机构**：根据上下文推断（小宁说→小Lin说）。**拿不准的不要硬改，列出来交付时问用户。**
- **用户亲口说的非常规说法（比如 K9）保持原样**，不要按常识纠正。
- 数字：`1,500` 写成 `1500`；金额、型号按口语原意写，比如「20差」要从上下文推断是不是「200刀」，推断的要告诉用户。

## 4. 自检清单（正式写入前）
- [ ] 每条的第一句能单独成立，不是「所以」「但是」开头（金句前置那句除外）。
- [ ] 每条的结尾是完整的一句话，没有半句。
- [ ] 调换顺序之后，代词（他、这个）的指代还对得上。
- [ ] 字幕里没有半个词、没有碎行、没有英文大小写不一致。
- [ ] `--dry-run` 里没有 ⚠ 超长行；没有以「的、了、着、地」开头的行。
- [ ] 写入后：字幕没有早于尾音消失，也没有晚于开口出现（用拼音频 + 识别检查）。
- [ ] 删掉的内容里没有必要的信息（比如「第二种」被删了，后面的「第三种」就显得突兀）。
