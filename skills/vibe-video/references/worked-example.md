# 一个填写示例：从点阵到彩格

这是用于理解模板的原创 12 秒图解方案，不是已经实现或验收的视频，也不声称逐帧复制 Opus。

任务：让观众看懂“同一组位置数据，可以用圆点或彩格显示；彩色还需要颜色字段”。借用 F03、F04、F06，避免把黑白孔点说成天然包含全部颜色。

规格：1920×1080、30 fps、360 帧。背景暖纸色，图解位于画面中上部；沿用实际项目字幕安全区。

| 帧区间 [起,止) | 对象动作 | 讲解/观看任务 |
| --- | --- | --- |
| 0–60 | 同一网格内的节点按行出现为深色圆点 | 先看到位置形成图案 |
| 60–105 | 节点保持；一个点的行/列简短高亮 | 明确“位置”这个变量 |
| 105–150 | 同一点旁补颜色字段，其他点保持 | 说明颜色是额外数据，不是凭空产生 |
| 150–225 | 每个节点原地变为对应彩格，启动时间错开 | 对应关系持续可追踪 |
| 225–300 | 完整图案保持，辅助标签退去 | 看清变化后的整体 |
| 300–360 | 镜头轻拉远，图案作为下一镜的固定对象 | 为后续应用场景留下连接 |

数据示例：`{"id":"r4c6","row":4,"col":6,"color":"#b85445"}`。圆点与色块都从这一份数据取坐标；颜色只在明确引入颜色字段后揭示。

合同：保留节点 ID、行列、网格间距；改变形状、尺寸、颜色；相机运动与节点运动分开。节点不能为了拼好花形跳到别处。

验收：在 149/188/225 帧追踪同一点，位置一致；在目标手机尺寸还能看出至少一组对应；片尾连接对象未无故消失。听审与实际画面检查完成前不写通过。

将这个示例推广到任何领域时，先核实“前态的信息足以产生后态吗”；若增加了信息，就在动画中显示它的来源。
