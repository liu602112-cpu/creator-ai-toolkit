# 从选题到内容方案

只对用户要展开的题工作，不把每次选题请求扩成整片制作。

## 开始前确定一句回答

写清“这条最后要回答什么”。这是核心问题、内容承诺或暂定结论，不是自动认定的事实。题仍在研究时，可以写“通过哪些证据判断”，无需抢先给未知答案。

将支撑材料区分为：用户实操/亲历、原始数据、官方或研究资料、个案、演示、编辑推理。材料存在与结论成立分开判断。没有的材料转成补采动作，例如“找一段自己没检索到素材的真实操作记录”，而非笼统写“需要丰富案例”。

## 选择结构

| 类型 | 适合材料 | 建议结构 | 不能替代的证据 |
|---|---|---|---|
| 问题解答 | 一个具体疑惑和可确定的答案 | 短答案 → 原因 → 操作/选择 → 例外 | 答案及适用边界 |
| 方法教程 | 自己能示范的流程 | 场景 → 判断标准 → 步骤 → 一次完整演示 → 检查办法 | 实际操作可行性 |
| 观点解释 | 有依据的判断或认知差 | 问题 → 判断 → 理由与证据 → 反例/边界 → 启示 | 核心论断依据 |
| 比较决策 | 两种以上选项与明确需求 | 适用人群 → 比较维度 → 同条件示例 → 如何选 → 限制 | 同条件的可比材料 |
| 案例/故事 | 真实事件、行动和变化 | 原状态 → 难题 → 选择与行动 → 变化 → 反思 | 事件、变化和关键语境 |
| 实验/测评 | 能说明方法和实测记录 | 问题 → 假设 → 方法 → 过程 → 结果 → 局限 | 实际过程和结果，不预写胜负 |

结构是选项，不是硬模板。教程无需人物冲突，案例不要编对白，反常识无需每条都有。长短由问题、素材和用户要求决定；估计时长以试读和实际操作复核，不将字数估算称为成片时长。

## 开场、标题和画面一起兑现

- 开场方向先描述真实看点：观众熟悉的困扰、可见差异、具体问题或明确结果。正文尽快提供第一份答案或证据，避免空喊“看完改变你”。
- 标题可以强调问题、判断标准或具体场景。多版本应是不同表达角度，不能让标题比材料的结论更强。“怎么判断是否需要补剂”不能写成“人人都必须吃”。
- 画面优先提供证据：操作录屏、实际物品、前后步骤、同条件比较、关键图表。每个建议说明它在证明或解释什么，以及素材是否已有。
- 补拍清单要适合用户条件；没有素材授权、不会动画或只有手机时，不把复杂拍摄当作必须。素材缺失先提替代形式或补采。

## 发出前的内容检查

是否一句话能复述；观众是否知道与自己有什么关系；理由是否具体；必要反差是否真实；证据能否支撑结论；有无实际动作或可带走的判断；标题的问题是否回答。

可借用SUCCESs、STEPPS和“获得感/惊喜感/表达力/感染力”检查一个明显弱项，不把每条稿件塞进所有原则。分享动机可以是帮朋友、表达身份或保存以后用；不能凭空煽动焦虑、制造稀缺或承诺效果。

## 请求完整稿时

事实足够就交付可直接念的稿和必要的简单画面建议。若仅缺可选包装不再卡住；缺核心事实时先完成不依赖它的段落或改成提纲，并列一个决定性的补采问题。

稿件可念只说明文字完成。视频拍摄、配音、剪辑、导出、上传和发布是另一个任务；不得因生成提纲就说成片已完成。
