# 历史数据和发布后复盘

把可见事实、可能原因和下一步测试分开。内置库没有播放/留存/评论文本，不能据它完成全部复盘。

## 先确认可比条件

确认这些数据是谁的、什么平台、什么阶段、什么形式、什么发布窗口、什么采集时间，是全量还是挑选的样本。只在同样定义下比较；累计互动会随视频年龄变化。

内置标题表缺少粉丝规模，多数缺日期，采集时间未统一记录，又是“爆款选题”收录样本。可报告“该作者在此收录样本中的互动中位数/相对位置”，不可称为完整账号基线、爆款率或全市场排行。没有账号名的S3不要强行合成一个账号。

相同标题记录可能是重发、不同作品或同作品不同抓取时间；没有作品ID先分别保留。分析稳定机制时说明身份无法确定，不把重复收录当独立成功次数；不要加总其互动当作品总量。

只有有分母才能算率：点赞/播放是点赞率的一种口径；收藏/点赞只能叫收藏与点赞的比值，不能冒称收藏率或播放量。缺失数不改成0；真实0保留，但时长0的含义未经确认。

## 分层诊断

| 观察材料 | 能讨论什么 | 暂不能断定什么 |
|---|---|---|
| 曝光、来源与触达 | 被哪些人看见、是否有足够样本 | 低曝光一定是选题错 |
| 点击/起播及封面标题 | 包装是否让目标人群愿意开始 | 仅凭点赞推断点击率 |
| 留存、平均观看及脚本 | 哪一段观众退出，是否迟迟没兑现 | 没曲线就定位“第7秒掉人” |
| 完播、收藏、分享和真实反馈 | 内容是否有用、可复用、被误解 | 互动高就等于满意或知识正确 |
| 新增关注与观众画像 | 是否吸引目标人群、是否值得追后续 | 所有高播放都适合账号 |
| 咨询、订单等明确转化数据 | 当前内容目标是否达成 | 有评论就等于成交 |

Appeal/Engagement/Satisfaction是理解框架，不是可还原的平台推荐权重。其它平台需用其实际可用指标解释，不照搬名称或机制。

## 回到发布前假设

例如原假设是“同类内容都只解释概念，我用实际操作会让用户能行动”。复盘先找用户是否理解了步骤、是否出现具体操作反馈，再看相似内容下的留存与收藏，而非只记播放涨跌。

下一轮尽量选一个能区分的变量：相同问题换开场、同类题补演示，或收窄人群。说明其它条件难以完全控制，单次变化不足以证明因果。多次同类观察可提高信心，不设机械的“发满N条就是真理”。

默认输出：3条以内可见事实、最可能的1–2个原因与未排除因素、下一条的具体改法、需要补什么数据。没有真实数据就只诊断选题与稿件，不假装做了效果复盘。

发现可复用机制时建议系列方向。长期权重、账号定位和栏目比例的修改要有具体证据并交给用户选择，不因一次结果静默改规则。
