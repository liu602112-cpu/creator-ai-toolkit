# 改稿与表达检查

## 按用户要求控制修改幅度

| 用户要求 | 合适的改动 | 应避免 |
|---|---|---|
| 润色、顺一点、改病句 | 调语序、消歧义、删赘词，保留结构、意思和声音 | 自动换观点、补数据、重写人设 |
| 更口语、更像我 | 用样本中的句长、称呼、解释方式和节奏改表达 | 强塞“兄弟姐妹们”、方言或参考作者经历 |
| 去AI味 | 删空转铺垫、虚假强调、同义重复，具体化真实内容 | 把正常术语全部删掉、加入假亲历 |
| 重写、提升逻辑 | 调顺序、补因果桥梁，把已有证据放到有关结论处 | 擅自扩大事实范围或改变结论 |
| 只改开头/结尾/标题 | 保留正文要求，在指定位置给可衔接版本 | 一并重写全文或重做选题 |
| 缩短、控制字数 | 留主张、必要证据、关键条件与动作，删背景及重复 | 删除“可能”“样本中”等限定，变成绝对结论 |
| 扩写、讲清楚 | 用现有事实补解释，可加明确的假设示例 | 凭空添加时间地点、对话、客户结果、研究 |
| 更有冲突/更能转化 | 把材料里的真实矛盾或疑虑讲清楚 | 造焦虑、造稀缺、夸大原稿 |
| 点评、诊断 | 指出具体句子、问题、原因和修法 | 用户只要评价时擅自给完整重写稿 |

先判断原稿的问题是观点、材料、结构还是语言。“文案不顺”不能一律当成润色能解决。关键证据缺失时先保留可用部分；只提出最影响结果的补料问题。

## 修改前的事实清单

内部标记要保留的主张、数据、对象、适用条件、经历、时间及产品条件。修改后逐项比较：

- 主体有没有从“这个客户”扩大成“所有用户”？
- 判断有没有从“可能”变成“必然”，从“相关”变成“导致”？
- 范围、周期、样本、代价有没有被删掉？
- 新增的例子是否清楚标为假设，而非用户亲历？
- CTA有没有新增未授权的价格、名额、赠品、截止日或承诺？

观点可以写得明确，事实的确定性不能靠改稿提高。用户要求保留的错别字与事实错误区别处理：纯语言可以修；事实或专业术语不确定时不要静默改成自认为正确的答案。

## 声音与“去AI味”

有原稿时先抽取：正式程度、常用称呼、句长、习惯解释方式、幽默位置、常用与禁用表达。只借用语言特征，不搬身份及经历。保留有辨识度且有意义的口头表达；逐字稿中的填充词可按目的压缩，不追求消除所有自然停顿。

检查句子的功能。删掉没有信息的宏大背景、无依据的“颠覆/顶级/暴涨”、重复总结、连续书面过渡。三句排比有三种新信息可以保留；只是换词说一件事时压缩。不要为了“更人味”故意加语病、强行对立或脏话。

口播一口气一层意思；重要结论前置。书面文案仍可用完整长句，只要关系清楚。把“用户价值最大化”改成用户能看到或做的事；没有实际材料时，保留具体问题，不填造数字假装具体。

## 长度与时长

用户给明确字数时先确定口径；不清楚时采用“不含空白的字符数”，包含标点和拉丁字符，并简短注明。中文汉字数可以另列，不能把两种口径混用。用户要“约300字”时不必追求一个字符不差。

用 `python scripts/measure_text.py <文本文件>` 获取客观长度。脚本提供不含空白字符数、汉字数等，不证明稿件可在指定秒数内念完。

若用户提供或已有真实测得的阅读速度，可以用 `--cpm <每分钟不含空白字符数>` 作粗估。未提供速度时只给明确标注的规划区间，考虑演示、停顿、英语和数字读法，不能声称满足精准秒数。最终以用户或配音的真实朗读为准。不要用未核验单位的CSV作品时长反推通用语速。

## 四轮编辑的实际判断

**结构**：先满足目标读者最想知道的事；因果衔接自然，背景比例适当，结尾回应开头。

**信息**：删重复，找证据与例子，补必要判断条件。资料不够时缩小结论，避免把待补素材写进完成稿。

**语言**：按听或读的场景调句长，把抽象表述改成动作和情境。称呼和语气符合用户原稿。

**可信度**：标题、正文、案例和CTA使用同一事实边界；医学/健身建议不得从参考口播直接视为正确知识。

评分只是编辑判断。没有播放、完播、转化等实测结果，不能用“93分”宣称爆款概率。用户未要求评分时，优先把问题改好，不输出评分仪式。
